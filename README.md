# Шелли

AI-агент для вашего VPS. Работает в терминале по SSH и в Telegram: берёт задачу,
выполняет команды и возвращает готовый результат.

## Что внутри

- **Ровно один инструмент** — `run_command`. Никакого лишнего реестра: Шелли может выполнять
  любую shell-команду от имени пользователя, под которым запущена.
- **Подтверждение опасных команд** — в терминале `y/N`, в Telegram кнопками «Да/Нет».
- **Один итоговый ответ в Telegram** — промежуточные реплики в чат не уходят. Все статусы идут в один анимированный rich-черновик с одним `draft_id`: `💬 Шелли думает`, `💬 Выполняю: <команда>`, `💬 Проверяю модель …`. Статус команды доставляется до её запуска и держится не меньше 1.5 с (а обычно до самого ответа). Итог приходит одним rich-сообщением и закрывает черновик.
- **Стриминг в терминале** — спиннер и пошаговый вывод реплик.
- **Ротация ключей и моделей** — если Gemini перегружен, Шелли показывает статус «Проверяю модель …» и пробует следующий ключ/модель. Ошибка 503 внутри потока теперь тоже запускает перебор.
- **Аудит** — все вызовы команд пишутся в `tools.log`.
- **Публичный бот** — `@shelly_ai` отвечает всем: помогает с вопросами и ведёт по установке, но не выполняет команды. Команды доступны только после собственной установки и подключения своего бота.
- **Изоляция пользователей** — каждому Telegram-ID свой агент и своя история; подтверждать команды может только владелец установки (`SHELLY_ADMIN_ID`).

## Как пользователь начинает

1. `/start` в `@shelly_ai` — одна кнопка «Создать бота». Предлагаемое имя вида `@shelly_ai_<цифры>_bot` сохраняется в `.bot_names.json` (права 600), чтобы не повторяться и после перезапуска.
2. Головной бот получает апдейт `managed_bot`, через `getManagedBotToken` забирает токен нового бота и присылает его вместе с командами установки и кнопкой «Перейти в бота».
3. Пользователь ставит Шелли на свой VPS (`install.sh` спрашивает токен и ключ Gemini) и дальше работает уже в своём боте.

Для шага 2 нужно включить **Bot Management Mode** у `@shelly_ai`: открыть [BotFather MiniApp](https://t.me/Botfather?startapp), выбрать бота → Bot Settings → Bot Management Mode. Без режима кнопка ведёт в BotFather, токен придётся вставить вручную.

## Установка

```bash
git clone https://github.com/namematthew-cyber/shelly.git shelly
cd shelly
python3 -m venv .venv
. .venv/bin/activate
pip install -e .
cp .env.example .env
chmod 600 .env
```

Заполни `.env`: ключ Gemini, токен бота из [@BotFather](https://t.me/BotFather),
свой Telegram ID (узнать можно у [@userinfobot](https://t.me/userinfobot)).

Быстрая настройка с вопросами и установкой systemd-сервиса:

```bash
sudo ./install.sh --service
```

## Как получить ключ Gemini

1. Открой [Google AI Studio — API keys](https://aistudio.google.com/app/apikey).
2. Войди в свой Google-аккаунт.
3. Нажми **Create API key** и выбери существующий проект или создай новый.
4. Скопируй ключ (начинается с `AIzaSy` или `AQ.`) и добавь в `.env`:
   ```ini
   GEMINI_API_KEYS=твой_ключ
   ```
   Несколько ключей перечисляются через запятую — Шелли переключится на следующий, если один перегружен или исчерпал квоту.
5. Не публикуй ключ. Если утёк — удали его в Google AI Studio и создай новый.
6. Бесплатной квоты хватает для старта; для постоянной работы включи billing в проекте.

Ту же инструкцию можно получить прямо в боте командой `/keys`.

## Запуск

```bash
shelly       # терминальный UI
shelly-tg    # Telegram-бот
```

Или как сервис (после `install.sh --service`):

```bash
systemctl status shelly-tg
journalctl -u shelly-tg -f
```

## Команды в Telegram

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и главное меню (без запуска агента) |
| `/menu` | Открыть главное меню заново |
| `/about` | Что такое Шелли |
| `/install` | Как установить на свой сервер, с кнопками копирования команд |
| `/keys` | Как получить ключ Gemini, со ссылкой на AI Studio |
| `/examples` | Готовые задачи, которые подставляются в поле ввода |
| `/security` | Как устроена защита секретов |
| `/clear` | Очистить историю разговора |
| `/help` | Справка |
| любой текст | Отправить задачу Шелли |

Внутри страниц есть кнопки «Меню» и «Закрыть»: при переходе старая страница удаляется, поэтому чат не засорён.

Статические страницы (`/start`, `/menu`, `/about`, `/install`, `/keys`, `/examples`, `/security`, `/clear`, `/help`) отправляются обычными HTML-сообщениями с inline-кнопками. Rich-сообщения остаются только у стриминга ответов.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `GEMINI_API_KEYS` | — | Ключи Gemini через запятую |
| `SHELLY_TG_TOKEN` | — | Токен Telegram-бота |
| `SHELLY_ADMIN_ID` | — | Разрешённый Telegram ID |
| `SHELLY_USER_NAME` | `хозяин` | Как звать пользователя |
| `SHELLY_GREETING` | `Здравствуй, {имя}. Что случилось?` | Приветствие |
| `SHELLY_MODELS` | 4 модели Gemini | Порядок fallback |
| `SHELLY_WORKDIR` | домашний каталог | Где выполняются команды |
| `SHELLY_STEP_LIMIT` | `12` | Максимум шагов агента на запрос |
| `SHELLY_HISTORY_LIMIT` | `40` | Размер истории перед урезкой |
| `SHELLY_COMMAND_TIMEOUT` | `120` | Таймаут команды, сек |
| `SHELLY_CONFIRM_TIMEOUT` | `180` | Сколько ждать подтверждения в TG, сек |
| `SHELLY_LONG_REQUEST_AFTER` | `20` | Когда долгий запрос дополнительно показывает редактируемое сообщение, сек |
| `SHELLY_THINK_EMOJI` | кастомный ID | Премиум-эмодзи анимации |
| `SHELLY_LOG_PATH` | `<пакет>/tools.log` | Журнал вызовов инструментов |
| `SHELLY_PROJECT_URL` | — | Ссылка на репозиторий, подставляется в `/about` и `/install` |
| `SHELLY_MASK_SECRETS` | `1` | Маскировать ключи/токены в выводе команд, логах и сообщениях |
| `SHELLY_CONFIRM_ALL` | `0` | Требовать подтверждение для любой команды, не только опасной |

Приоритет: переменные окружения → `.env` → значения по умолчанию.
Путь к `.env` можно переопределить через `SHELLY_ENV_FILE`.

## Если Gemini отдаёт 503

Шелли сама перебирает все модели и ключи из `SHELLY_MODELS` / `GEMINI_API_KEYS` и делает короткий backoff.
Если все ответили `503 UNAVAILABLE` («high demand»), она не падает с техническим traceback, а пишет понятное сообщение
и предлагает повторить через минуту. То же относится к `429` (квота), недействительному ключу и таймаутам.

## Безопасность

- `run_command` выполняется с правами пользователя, под которым запущена Шелли.
  Не запускайте её от root без необходимости — или задайте `SHELLY_WORKDIR` и ограничьте
  пользователя на уровне системы.
- Опасные шаблоны (`rm -rf`, `mkfs`, `shutdown`, …) требуют подтверждения.
  Свой список — через `SHELLY_DANGEROUS_PATTERNS`.
- `.env` должен быть с правами `600`: токены и ключи не должны попадать в чат или репозиторий.
- Вывод команд, аргументы инструмента и аудит-лог проходят через маскировку секретов
  (`SHELLY_MASK_SECRETS=1`): даже `cat .env` не покажет токены в чате и не уйдёт в Gemini.
- `SHELLY_CONFIRM_ALL=1` включает подтверждение каждой команды — полезно для параноидального режима.
- systemd-юнит из `install.sh --service` включает консервативный харденинг (`UMask=0077`,
  `PrivateTmp`, защита kernel/cgroup). Полная изоляция не включена намеренно: Шелли — инструмент
  админа и должна уметь запускать системные команды.
- Проверить установку можно командой `shelly-doctor`: она проверит `.env`, права, доступность
  Telegram API и Gemini API.
- `SHELLY_ADMIN_ID` — владелец установки: только он может подтверждать команды. Публичный бот отвечает всем, но не имеет инструментов и не исполняет команды. Ключи и токены в чате не запрашиваются.
